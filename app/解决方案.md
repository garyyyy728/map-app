# 🔧 问题解决方案

## ❌ 问题分析

您遇到的错误：`[WinError 10061] 由于目标计算机积极拒绝，无法连接`

**根本原因：代理服务器未运行**

✅ .env 文件已正确配置（代理端口：7890）
❌ 但代理服务器（Clash/V2rayN）没有运行

---

## ✅ 解决步骤（3步）

### 步骤 1️⃣：启动代理工具

您需要先启动代理工具（选择其中一个）：

#### 🎯 推荐：Clash for Windows
1. 打开 Clash for Windows
2. 确保显示 "Running" 或 "已启动"
3. 检查端口设置（默认应该是 7890）
4. 选择一个节点（推荐美国/日本/新加坡）

#### 或者：V2rayN
1. 打开 V2rayN
2. 启动系统代理
3. 如果使用 V2rayN，需要修改 .env 中的端口：
   ```
   HTTP_PROXY=http://127.0.0.1:10809
   HTTPS_PROXY=http://127.0.0.1:10809
   ```

#### 或者：其他代理工具
如果使用其他工具，确保：
- 代理服务正在运行
- HTTP 代理端口与 .env 中配置的一致

---

### 步骤 2️⃣：验证代理是否工作

运行以下命令测试：

```powershell
# 测试代理连接
$env:HTTP_PROXY="http://127.0.0.1:7890"
$env:HTTPS_PROXY="http://127.0.0.1:7890"
curl https://www.google.com
```

如果能访问 Google，说明代理工作正常！✅

---

### 步骤 3️⃣：启动后端服务

```powershell
python main.py
```

服务启动后，您应该看到类似输出：
```
INFO:     Starting Gemini API 后台服务 v1.0.0
INFO:     Docs available at http://0.0.0.0:8000/docs
INFO:     Uvicorn running on http://0.0.0.0:8000
```

## 🔍 如果 Clash 端口不是 7890

### 检查 Clash 的实际端口：

1. 打开 Clash for Windows
2. 点击 "Settings" 或 "设置"
3. 查看 "Port" 或"端口"设置（在 "General" 或"常规"下）
4. 记下 HTTP 端口号（例如：7890、7891 等）

### 更新 .env 文件：

如果端口不是 7890，修改 `.env` 文件中的配置：

```env
HTTP_PROXY=http://127.0.0.1:YOUR_PORT
HTTPS_PROXY=http://127.0.0.1:YOUR_PORT
```

（把 `YOUR_PORT` 替换为实际端口号）

## 🆘 常见问题

### Q1: 我没有代理工具怎么办？

**方案 A（推荐）：安装 Clash for Windows**
1. 下载：https://github.com/Fndroid/clash_for_windows_pkg/releases
2. 需要订阅节点（可以购买或使用免费节点）
3. 配置简单，界面友好

**方案 B：使用 VPN**
如果您有 VPN（如 ExpressVPN、NordVPN），连接后可以直接使用，不需要配置代理。

### Q2: 代理启动了但还是报错？

1. **检查端口号是否匹配**
   ```powershell
   netstat -ano | findstr ":7890"
   ```
   如果没有输出，说明 7890 端口未监听，需要调整端口号

2. **检查节点是否可用**
   - 在 Clash 中切换其他节点
   - 选择延迟较低的节点

3. **重启代理工具**
   - 完全退出代理工具
   - 重新启动

### Q3: 启动服务时提示端口 8000 被占用？

修改 `.env` 中的端口：
```env
PORT=8001
```

## 💡 提示

1. **保持代理持续运行**
   - 在使用 Gemini API 期间，代理工具必须保持运行
   - 关闭代理会导致连接失败

2. **选择合适的节点**
   - 美国、日本、新加坡节点通常效果最好
   - 避免选择延迟过高的节点

3. **生产环境建议**
   - 部署到国外服务器（AWS、GCP、Azure）
   - 无需代理，更稳定
