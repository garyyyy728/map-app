# 🔧 如何切换代理节点 - 详细教程

## 📌 重要提示

**切换节点的目的：** 选择支持 Gemini API 的地区节点（美国、日本、新加坡等）

**必须配置：**
1. ✅ 代理模式：**全局模式**
2. ✅ 节点位置：**美国/日本/新加坡**

---

## 方法一：Clash for Windows 用户

### 步骤 1: 打开 Clash

1. 在系统托盘找到 Clash 图标（通常是一只猫）
2. 双击打开 Clash for Windows 主界面

### 步骤 2: 切换到全局模式

1. 在主界面顶部，找到 **"General"（常规）** 标签页
2. 找到 **"System Proxy"（系统代理）** 或 **"Mode"（模式）** 设置
3. 选择 **"Global"（全局）** 模式

**或者：**
1. 点击左侧的 **"Proxies"（代理）** 标签页
2. 在顶部切换模式为 **"Global"（全局）**

```
模式选项：
❌ Rule（规则）    - 不要选这个
❌ Direct（直连）  - 不要选这个
✅ Global（全局）  - 选择这个！
```

### 步骤 3: 选择节点

1. 在 **"Proxies"（代理）** 标签页
2. 查看节点列表（通常在 "PROXY" 或代理组下）
3. 找到节点标注的地区：
   ```
   ✅ 推荐选择：
   🇺🇸 United States（美国）
   🇺🇸 US-xxx
   🇯🇵 Japan（日本）
   🇯🇵 JP-xxx
   🇸🇬 Singapore（新加坡）
   🇸🇬 SG-xxx
   
   ❌ 不推荐：
   🇭🇰 Hong Kong（香港）
   🇨🇳 China（中国）
   🇹🇼 Taiwan（台湾）
   ```

4. **点击节点名称** 旁边的圆圈或选择按钮，选中该节点
5. 查看延迟（Delay）：
   - ✅ < 300ms：最佳
   - ⚠️ 300-500ms：可用
   - ❌ > 500ms：不推荐

### 步骤 4: 测试节点

点击节点旁边的 **"测速"** 图标（通常是闪电⚡或刷新🔄图标）

## 方法二：V2rayN 用户

### 步骤 1: 打开 V2rayN

1. 在系统托盘找到 V2rayN 图标（通常是 V 字母）
2. 右键点击图标

### 步骤 2: 切换到全局模式

右键菜单中选择：
```
系统代理
  └─ ✅ 自动配置系统代理
  └─ ❌ 清除系统代理
  └─ ❌ 不改变系统代理

Http代理
  └─ ❌ PAC模式
  └─ ✅ 全局模式  ← 选择这个！
  └─ ❌ 不改变
```

**重要：** 必须同时勾选：
- "自动配置系统代理"
- "全局模式"

### 步骤 3: 选择节点

1. 双击系统托盘的 V2rayN 图标，打开主窗口
2. 查看服务器列表，每行显示一个节点
3. 查看 **"别名"** 或 **"备注"** 列，找到地区标识：

```
列表示例：
┌────────────────────────────────────────────┐
│ 别名              地址          延迟  测速  │
├────────────────────────────────────────────┤
│ 🇺🇸 美国-1        xxx.xxx       245ms  ✅  │  ← 选这个
│ 🇯🇵 日本-东京     xxx.xxx       123ms  ✅  │  ← 或这个
│ 🇭🇰 香港-1        xxx.xxx       45ms   ❌  │  ← 不要选
│ 🇸🇬 新加坡        xxx.xxx       189ms  ✅  │  ← 也可以
└────────────────────────────────────────────┘
```

4. **双击节点** 或 **右键 → 设为活动服务器**

### 步骤 4: 测试节点

1. 选中节点后，点击顶部菜单：**"测试服务器真连接延迟"**
2. 等待测速完成
3. 查看 **"延迟"** 列的数值

## 方法三：其他代理工具（通用）

### Shadowsocks 用户

1. 右键系统托盘图标
2. **系统代理模式** → 选择 **"全局模式"**
3. **服务器** → 选择美国/日本/新加坡节点

### Qv2ray 用户

1. 打开 Qv2ray 主界面
2. 点击左侧节点列表
3. 选择美国/日本/新加坡节点
4. 右键 → **连接**
5. 设置 → 入站设置 → **系统代理模式** → **全局**

## 🧪 测试配置是否正确

### 测试 1: 检查代理是否运行

打开 PowerShell，运行：

```powershell
Test-NetConnection -ComputerName 127.0.0.1 -Port 7890
```

**期望输出：**
```
TcpTestSucceeded : True
```

### 测试 2: 检查节点位置

访问这个网站查看您的 IP 位置：
```
https://ipinfo.io
```

**期望结果：** 显示美国/日本/新加坡等地区

### 测试 3: 测试 Gemini API

在项目目录运行：

```powershell
python test_api_endpoint.py
```

**期望输出：**
```
测试 2: 使用代理
状态码: 200
✅ 成功！找到 XX 个模型
```

如果显示 **400 错误**：
1. 尝试切换到其他节点
2. 确认已启用全局模式
3. 重启代理工具

- [ ] **运行 `Test-NetConnection 127.0.0.1 -Port 7890` 成功**
- [ ] **运行 `python test_api_endpoint.py` 返回状态码 200**

## 🎯 常见问题

### Q1: 我不知道哪个节点是美国的？

**答：** 查看节点名称中的关键字：
```
美国/US/United States/America/Los Angeles/San Francisco
日本/JP/Japan/Tokyo
新加坡/SG/Singapore
```

如果节点名称不清楚，尝试每个节点，运行 `python test_api_endpoint.py` 测试。

### Q2: 所有节点都是 400 错误怎么办？

**答：** 可能原因：
1. 您的代理服务商的所有节点都在不支持的地区
2. 需要购买/订阅包含美国节点的代理服务
3. 考虑使用 VPN 而不是代理

### Q3: 全局模式会影响其他应用吗？

**答：** 会的，全局模式下：
- ✅ 所有网络流量都通过代理
- ⚠️ 访问国内网站可能变慢
- 💡 测试完成后可以切回规则模式

**解决方案：** 只在使用 Gemini API 时开启全局模式

### Q4: 可以只为 Python 设置代理吗？

**答：** 可以，但不推荐。全局模式最稳定。

如果一定要这样，在 `.env` 文件中已经配置：
```
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
```

但您的代理工具仍需要运行，且选择正确的节点。

## 💡 提示

- **节点质量很重要**：延迟低、速度快的节点会提升 API 响应速度
- **多试几个节点**：如果一个不行，尝试同地区的其他节点
- **高峰期切换**：某些节点在高峰期可能不稳定，可以切换到其他节点
- **定期测速**：节点速度会变化，定期测速选择最优节点
