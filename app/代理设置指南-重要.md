# 🚨 代理设置指南 - 重要说明

## 问题诊断结果

经过测试发现：
- ✅ 您的代理工具（端口 7890）正在运行
- ✅ 代理可以访问 Google.com
- ❌ **但代理无法访问 Gemini API**

这说明问题不在代码配置，而在代理设置本身。

---

## 🔧 解决步骤

### 步骤 1: 检查代理模式

打开您的代理工具（Clash/V2rayN），确保使用以下模式之一：

**Clash for Windows:**
1. 打开 Clash
2. 点击"代理"或"Proxies"
3. 选择 **"全局"（Global）** 模式
   - ❌ 不要使用"规则"或"直连"模式
   - ❌ 不要使用"PAC"模式

**V2rayN:**
1. 打开 V2rayN
2. 右键点击系统托盘图标
3. 选择 **"系统代理" > "全局模式"**

### 步骤 2: 选择正确的代理节点

**重要！** Gemini API 只在以下地区可用：

✅ **推荐节点位置：**
- 🇺🇸 美国（优先）
- 🇯🇵 日本
- 🇸🇬 新加坡
- 🇪🇺 欧洲国家（英国、德国、法国等）

❌ **不支持的位置：**
- ❌ 中国大陆
- ❌ 香港（部分节点可能不稳定）
- ❌ 某些中东和非洲国家

**如何更换节点：**

**Clash:**
1. 打开 Clash
2. 点击"代理"标签页
3. 在代理组中选择 **美国** 或 **日本** 节点
4. 确保选择延迟较低的节点（< 300ms）

**V2rayN:**
1. 打开 V2rayN 主窗口
2. 查看服务器列表
3. 双击选择美国或日本的服务器
4. 查看"备注"或"地区"列

### 步骤 3: 测试代理是否正确配置

运行测试脚本：

```bash
python test_api_endpoint.py
```

**期望输出：**
```
测试 2: 使用代理
状态码: 200
✅ 成功！找到 X 个模型
第一个模型: models/xxx
```

如果仍然显示 400 错误，说明：
1. 节点位置不对
2. 或者需要切换到其他节点

### 步骤 4: 重启服务

代理配置正确后，重启后端服务：

```bash
# 1. 停止当前服务（Ctrl+C 或关闭窗口）

# 2. 重新启动
python main.py
```

### 步骤 5: 测试图片分析

```bash
python test_image_api.py
```

## 💡 常见问题

### Q1: 代理模式如何选择？

**答：** 必须使用 **全局模式（Global）**

| 模式 | 是否可用 | 说明 |
|------|---------|------|
| 全局模式 | ✅ | 所有流量通过代理 |
| 规则模式 | ❌ | 只有匹配规则的才走代理，Gemini API 可能不在规则中 |
| PAC模式 | ❌ | 自动判断，可能将 Gemini API 判断为直连 |
| 直连模式 | ❌ | 不使用代理 |

### Q2: 为什么代理能访问 Google 但不能访问 Gemini API？

**答：** 这可能是因为：
1. 您的代理使用了"规则模式"，Gemini API 不在规则列表中
2. 代理节点位置不对（如香港、台湾等可能不稳定）
3. Gemini API 对代理检测更严格

### Q3: 我应该选择哪个地区的节点？

**答：** 优先级如下：
1. 🥇 美国西海岸（延迟较低）
2. 🥈 日本
3. 🥉 新加坡
4. 欧洲国家

### Q4: 节点延迟多少合适？

**答：** 
- ✅ < 300ms：最佳
- ⚠️ 300-500ms：可用，但较慢
- ❌ > 500ms：不推荐

### Q5: 我没有合适的代理节点怎么办？

**答：** 有几个选择：
1. 使用其他代理服务（推荐使用支持美国/日本节点的服务）
2. 使用 VPN（ExpressVPN、NordVPN 等）
3. 部署到国外服务器（AWS、GCP、Vercel 等）
